# 0002 - 严格串行转码执行与并发传输解耦模型

## 背景与决策

斐讯 N1（4核 Cortex-A53，2GB 内存）与低配树莓派在多路转码时存在极高发热与内存耗尽（OOM）风险。为保证服务高可用且不拖垮设备，必须控制并发。

我们决定在转码后端采用**串行转码执行 + 并发文件传输**的解耦模型：上传接口与下载接口支持并发 HTTP 传输，而实际的 FFmpeg 转码执行器采用单通道 FIFO 队列，一次仅允许一个视频任务处于转码状态。

### 用户补充细节

> **用户针对该项提出的补充与扩展：**
> 1. **认可并发与转码隔离机制**：用户针对任务调度选择方案 B（“串行转码 + 并行传输”），即文件上传与排队不受转码状态阻塞，多个文件可以预先进入待处理队列。
> 2. **硬件过载保护原则**：在低功耗 ARM 硬件条件下，转码计算属于重度 CPU 绑定型密集操作，必须严格单任务互斥，下一个任务的触发严格绑定在前序任务完成、失败或被取消之后。
