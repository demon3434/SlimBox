# 0006 - 基于 Go 语言的低开销 ARM64 后端架构选型

## 背景与决策

斐讯 N1 设备受限于晶晨 S905D 处理器的计算瓶颈与仅 2GB 的 RAM 物理上限，高内存占用或高解释器开销的语言环境容易在后台引起垃圾回收抖动或内存争抢，从而挤占 FFmpeg 编码所需的内存空间。

我们决定采用 Go 语言作为 SlimBox 后端核心服务的开发语言，以前后端解耦静态打包的形式交付，运行在 ARM64 Docker 容器中。

### 用户补充细节

> **用户针对该项提出的补充与扩展：**
> 1. **技术栈明确敲定**：用户确认选择方案 A（Go 语言后端 + 轻量前端），排除高内存占用的解释型语言方案。
> 2. **硬件友好与资源最大化释放**：Go 编译输出单静态二进制文件，启动内存通常仅 15~30MB，无虚拟机与额外解释器驻留负担，能将 N1 宝贵的 2GB 内存和 4 核 CPU 资源最大限度留给转码主进程使用。
