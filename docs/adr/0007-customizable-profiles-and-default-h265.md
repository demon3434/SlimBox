# 0007 - 预设档位自定义持久化与默认 H.265 编码器模型

## 背景与决策

用户对压制效率与文件体积的诉求存在明显倾向：文件体积必须尽可能小，同时预设档位不能是一成不变的死规则，需要允许使用者依据自身观影偏好定制并固化。

我们决定在系统中默认采用 H.265 (libx265) 作为各分辨率档位的基准视频编码器；从 360p 到 4K 的每个档位均对应一个标准命令行枚举名称，并在各档位中提供 H.264 与 H.265 的无缝切换。同时，提供“保存当前自定义参数为我的预设”与“一键恢复出厂默认值”功能。

### 用户补充细节

> **用户针对该项提出的补充与扩展：**
> 1. **默认编码器指向 H.265**：用户明确强调“且每个档次都可以选择H265或H264。默认是H265，因为我追求文件体积小”，因此即便在低算力 ARM 设备上 H.265 耗时更长，系统仍严格尊重用户的体积优先诉求，将 H.265 设为出厂默认编码器。
> 2. **参数可调与自存预设**：“每一档的推荐参数，先按照你的预设作为默认值，但是用户也可以自行调整每一档的参数，可以保存自己的预设，也可以恢复默认值。”系统必须支持两级配置：只读的工厂默认值与可变的用户保存值。
> 3. **CLI 枚举映射**：“每个档位可以作为命令行参数的一个枚举值，对应了一组预设参数。”CLI 客户端可通过 `--profile 720p` 或 `--profile 1080p` 直接引用该档位背后完整的参数包。
