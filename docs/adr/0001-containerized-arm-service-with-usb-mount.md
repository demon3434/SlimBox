# 0001 - 容器化运行与外挂 USB 存储架构

## 背景与决策

斐讯 N1 与部分早期树莓派设备板载存储（如 N1 的 8GB eMMC）空间极小，无法承载多部电影电视剧的高清原文件及转码产物。同时，系统需要能够作为内网微服务长期稳定运行。

我们决定将 SlimBox 整体封装为 Docker 容器镜像发布，作为内网视频压缩微服务；存储策略上，由用户为 ARM 设备挂载物理 USB 外接硬盘，并通过 Docker 卷映射（Volume Mount）挂载到容器内部的工作目录，N1 本身不挂载外部网络设备（如 SMB/NFS）。

### 用户补充细节

> **用户针对该项提出的补充与扩展：**
> 1. **外挂存储归属明确**：用户明确表示“我会给这些arm设备挂载USB硬盘，N1自己不会挂载视频文件所在设备的磁盘作为NFS/SMB硬盘”。因此系统摒弃在 N1 系统层自动挂载第三方网络共享磁盘的复杂网络文件系统逻辑，直接基于外接物理 USB 块设备挂载点运行。
> 2. **交付形态约束**：明确“本程序最终要封装成docker容器，作为内网的压缩服务”，所有运行依赖（包括 FFmpeg、编解码库、运行时环境）均封装在 Dockerfile 构建出的镜像内，简化 ARM 架构（linux/arm64, aarch64）上的依赖安装与内网部署门槛。
